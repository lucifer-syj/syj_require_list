# 窗口吸附、预览、自动隐藏功能需求文档

## 1. 功能概述

实现桌面悬浮窗口的边缘吸附、拖动预览、自动隐藏功能，提升用户体验。

## 2. 功能列表

### 2.1 窗口边缘吸附
当用户拖动窗口靠近屏幕边缘时，窗口自动吸附到边缘并调整尺寸。

### 2.2 拖动预览
在拖动过程中，当窗口靠近边缘时，实时显示吸附后的预览效果。

### 2.3 自动隐藏
窗口吸附到边缘后，自动隐藏大部分内容，只保留一条边缘可见。鼠标悬停时重新显示。

## 3. 详细交互流程

### 3.1 拖动预览流程

**步骤1：用户开始拖动**
- 用户操作：鼠标按下标题栏并移动
- 系统响应：
  - 调用 Rust 命令 `start_position_tracking()` 启动位置轮询
  - 调用 Tauri API `startDragging()` 开始原生拖动
  - 设置前端状态 `isDragging = true`
- 用户看到：
  - 窗口跟随鼠标移动（原生拖动体验）

**步骤2：窗口靠近边缘**
- 触发条件：
  - 距离屏幕边缘 **10px** 以内
  - 支持的边缘：**左、右、上**（不支持下边缘）
- 系统响应：
  - Rust 后端检测到靠近边缘
  - 创建/显示独立的预览窗口
  - 计算预览窗口的位置和尺寸（根据吸附边缘）
  - 更新预览窗口到计算的位置
- 用户看到：
  - 半透明的灰色预览框出现，显示吸附后的窗口位置和尺寸
  - 预览框有不透明的边框，清晰可见

**步骤3：拖动过程中**
- 用户操作：继续拖动窗口
- 系统响应：
  - Rust 后端每 50ms 检查一次主窗口位置
  - 实时计算与边缘的距离
  - 如果仍在 10px 范围内，更新预览窗口位置
  - 如果离开 10px 范围，隐藏/销毁预览窗口
- 用户看到：
  - 预览框跟随窗口位置实时变化
  - 窗口离开边缘时，预览框消失

**步骤4：松开鼠标**
- 用户操作：松开鼠标左键
- 系统响应：
  - `startDragging()` 返回
  - 调用 Rust 命令 `stop_position_tracking()` 停止轮询
  - 检查是否有预览窗口存在
  - 如果有预览：调用 `snap_to_edge()` 执行吸附，保存原始状态
  - 如果没有预览：窗口停在当前位置，不做任何处理
  - 销毁预览窗口
  - 设置前端状态 `isDragging = false`
- 用户看到：
  - 如果有预览：窗口瞬间吸附到预览框的位置和尺寸
  - 如果没有预览：窗口停在松开鼠标的位置

### 3.2 窗口吸附流程

**吸附到左边缘**
- 窗口位置：
  - x 坐标：`screenX`（显示器左边缘）
  - y 坐标：`screenY`（显示器上边缘）
- 窗口尺寸：
  - 宽度：保持原窗口宽度
  - 高度：`screenHeight`（整个屏幕高度）

**吸附到右边缘**
- 窗口位置：
  - x 坐标：`screenX + screenWidth - windowWidth`（显示器右边缘减去窗口宽度）
  - y 坐标：`screenY`（显示器上边缘）
- 窗口尺寸：
  - 宽度：保持原窗口宽度
  - 高度：`screenHeight`（整个屏幕高度）

**吸附到上边缘**
- 窗口位置：
  - x 坐标：保持当前 x 坐标（不改变水平位置）
  - y 坐标：`screenY`（显示器上边缘）
- 窗口尺寸：
  - 宽度：保持原窗口宽度
  - 高度：保持原窗口高度

**吸附后的窗口状态**
- 窗口强制置顶（`alwaysOnTop = true`）
- 窗口可以继续拖动（拖动时立即恢复原始状态）
- 窗口可以调整大小（调整大小时取消吸附状态）

### 3.3 自动隐藏流程

**步骤1：吸附完成后**
- 触发条件：
  - 吸附后延迟 **1 秒**
- 系统响应：
  - 根据吸附边缘，计算隐藏位置：
    - 左边缘：`x = screenX - (windowWidth - 2)`（向左移出屏幕，只留 2px）
    - 右边缘：`x = screenX + screenWidth - 2`（向右移出屏幕，只留 2px）
    - 上边缘：`y = screenY - (windowHeight - 2)`（向上移出屏幕，只留 2px）
  - 使用平滑动画（300ms 过渡）移动窗口到隐藏位置
  - 调用 Rust 命令 `start_mouse_tracking()` 启动鼠标追踪
  - 监听屏幕边缘 **5px** 范围内的鼠标位置
  - 设置前端状态 `isHidden = true`
- 用户看到：
  - 窗口平滑地滑出屏幕，只留 2px 边缘可见
  - 动画流畅自然（300ms）

**步骤2：鼠标悬停显示**
- 触发条件：
  - 鼠标进入屏幕边缘 **5px** 范围内（根据吸附边缘判断）
  - 立即触发，无延迟
- 系统响应：
  - Rust 后端检测到鼠标进入触发区域
  - 发送事件到前端
  - 前端调用 Rust 命令 `show_window()`
  - 窗口平滑移回吸附位置（300ms 过渡）
  - 取消自动隐藏定时器（如果有）
  - 设置前端状态 `isHidden = false`
- 用户看到：
  - 窗口平滑地滑入屏幕，恢复到吸附位置
  - 动画流畅自然（300ms）

**步骤3：鼠标离开隐藏**
- 触发条件：
  - 鼠标离开窗口区域和边缘触发区域（5px）
  - 离开后延迟 **1 秒**
- 系统响应：
  - Rust 后端检测到鼠标离开
  - 发送事件到前端
  - 前端启动 1 秒定时器
  - 定时器到期后，调用 Rust 命令 `hide_window()`
  - 窗口平滑移动到隐藏位置（300ms 过渡）
  - 设置前端状态 `isHidden = true`
- 用户看到：
  - 鼠标离开 1 秒后，窗口平滑地滑出屏幕
  - 动画流畅自然（300ms）

**步骤4：取消吸附**
- 触发条件：
  - 用户拖动窗口，且窗口移动距离超过 **50px**（远离吸附边缘）
- 系统响应：
  - 调用 Rust 命令 `stop_mouse_tracking()` 停止鼠标追踪
  - 恢复原始窗口尺寸（保存的 `originalSize`）
  - 恢复原始窗口位置（保存的 `originalPosition`）
  - 恢复原始置顶状态（保存的 `originalAlwaysOnTop`）
  - 清除吸附状态（`isSnapped = false`, `snapEdge = 'none'`）
  - 清除隐藏状态（`isHidden = false`）
- 用户看到：
  - 窗口瞬间恢复到吸附前的尺寸和位置
  - 窗口可以正常拖动

## 4. 预览框视觉规格

### 4.1 预览框的实现方式
- **实现方式**：独立的 Tauri 窗口（选项B）
- **为什么选择这种方式**：
  - 主窗口使用 `startDragging()` 时，JavaScript 可能被阻塞，无法更新 DOM
  - 独立窗口有自己的渲染进程，不受主窗口影响
  - Rust 后端可以直接控制预览窗口，实时更新位置
  - 性能更好，更流畅

### 4.2 预览框的外观
- 背景颜色：灰色 `#808080`
- 透明度：`0.2`（整体窗口透明度）
- 边框：`3px` 实线，不透明的灰色 `#606060`
- 其他效果：
  - 无阴影
  - 无圆角
  - 无动画（位置变化是瞬间的，不需要过渡动画）

### 4.3 预览框的位置和尺寸
- 左边缘预览：
  - 位置：`x = screenX`, `y = screenY`
  - 尺寸：`width = 主窗口宽度`, `height = screenHeight`
- 右边缘预览：
  - 位置：`x = screenX + screenWidth - 主窗口宽度`, `y = screenY`
  - 尺寸：`width = 主窗口宽度`, `height = screenHeight`
- 上边缘预览：
  - 位置：`x = 主窗口当前 x`, `y = screenY`
  - 尺寸：`width = 主窗口宽度`, `height = 主窗口高度`

### 4.4 预览框的层级
- 预览框在主窗口**上方**（通过 `alwaysOnTop = true` 实现）
- 预览框置顶（`alwaysOnTop = true`）
- 预览框不可点击（`focusable = false`，鼠标事件穿透）

## 5. 技术实现要求

### 5.1 拖动实现方式
- **使用 Tauri 的 `startDragging()` API**
- **原因**：
  - 保持原生拖动体验，流畅度最好
  - 用户期望原生的拖动手感
  - 虽然可能阻塞 JavaScript，但通过 Rust 后端轮询解决位置检测问题

### 5.2 位置检测方式
- **Rust 后端轮询**（选项C）
- **检测频率**：每 **50ms** 检查一次（约 20fps）
- **实现方式**：
  - 在独立的 Tokio 任务中运行轮询
  - 不阻塞主线程和 JavaScript
  - 检测到边缘时，直接更新预览窗口（不需要通知前端）

### 5.3 预览框更新方式
- **Rust 后端直接更新预览窗口**
- **更新频率**：每 50ms（与位置检测同步）
- **实现方式**：
  - 使用 Tauri 窗口 API：`set_position()`, `set_size()`
  - 在 Rust 轮询任务中直接调用，无需前端参与

### 5.4 状态管理
- **需要保存的状态**：
  - `isSnapped`: 是否吸附（boolean）
  - `snapEdge`: 吸附到哪个边缘（'left' | 'right' | 'top' | 'none'）
  - `originalSize`: 原始窗口尺寸（{ width, height }）
  - `originalPosition`: 原始窗口位置（{ x, y }）
  - `originalAlwaysOnTop`: 原始置顶状态（boolean）
  - `isHidden`: 是否隐藏（boolean）
  - `screenInfo`: 当前显示器信息（{ x, y, width, height, scaleFactor }）
  - `isDragging`: 是否正在拖动（boolean）
- **状态保存位置**：
  - 前端：Pinia store（用于 UI 状态和逻辑控制）
  - Rust 后端：全局状态（用于轮询和窗口控制）

### 5.5 性能要求
- 预览框更新流畅度：**20fps**（50ms 间隔）
- 可接受的延迟：**50ms**
- CPU 占用率：轮询时 **< 5%**

## 6. 边界情况处理

### 6.1 多显示器
- **支持多显示器**
- **处理方式**：
  - 每个显示器独立吸附
  - 使用 `currentMonitor()` API 获取当前窗口所在的显示器
  - 每次检测位置时都获取当前显示器信息
  - 跨显示器拖动时自动切换显示器信息
  - 所有位置计算都基于当前显示器的偏移量（screenX, screenY）

### 6.2 窗口已在边缘
- 窗口启动时不自动吸附（即使窗口位置在边缘）
- 只有用户主动拖动窗口才触发吸附
- 如果窗口已吸附，再次拖动时立即恢复原始状态（见 3.3 步骤4）

### 6.3 从吸附状态拖动
- 用户拖动已吸附的窗口时：
  - **立即恢复原始尺寸和位置**（在 `startDrag` 函数开始时）
  - 不等待窗口移动距离
  - 立即清除吸附状态
  - 停止鼠标追踪
  - 取消自动隐藏
- 恢复到吸附前保存的原始位置和尺寸

### 6.4 窗口尺寸限制
- 窗口遵守 `tauri.conf.json` 中的最小/最大尺寸限制
- 吸附时如果计算的尺寸超出限制，使用限制值
- 例如：如果屏幕高度超过最大高度限制，使用最大高度

### 6.5 快速拖动
- 用户快速拖动窗口穿过边缘，只要进入 10px 范围就触发预览
- 不需要停留时间
- 避免误触发：只有松开鼠标时才真正吸附（有预览才吸附）

## 8. 实现优先级

**采用分阶段实现策略：**

**第一阶段（MVP - 最小可行产品）：窗口吸附**
- 检测边缘距离（10px）
- 松开鼠标时吸附
- 保存和恢复原始状态
- 不包含预览和隐藏功能
- 目标：验证吸附逻辑的正确性

**第二阶段：拖动预览**
- 创建独立预览窗口
- Rust 后端轮询位置（50ms）
- 实时更新预览窗口
- 目标：实现实时预览效果

**第三阶段：自动隐藏**
- 延迟隐藏（1秒）
- 平滑动画（300ms）
- 鼠标追踪（5px 触发区域）
- 悬停显示/离开隐藏
- 目标：完整的自动隐藏体验

## 11. 实际实现说明（2025-12-21 更新）

### 11.1 与原需求的主要差异

**拖动实现方式的变更：**
- **原计划**：使用 `startDragging()` API + Rust 后端轮询
- **实际实现**：自定义拖动（mousedown/mousemove/mouseup）
- **变更原因**：`startDragging()` 立即返回，无法准确检测鼠标松开时机，导致吸附时机不正确
- **实际效果**：60fps 节流，使用 RAF 优化，拖动流畅

**预览框实现方式的变更：**
- **原计划**：Rust 后端轮询更新预览窗口
- **实际实现**：前端在拖动过程中更新预览窗口
- **变更原因**：自定义拖动后，前端可以直接控制，无需 Rust 轮询
- **实际效果**：100ms 节流（10fps），预览流畅

**自动隐藏参数的调整：**
- **可见区域**：2px → **10px**（用户反馈 2px 太窄，鼠标难以触发）
- **自动隐藏延迟**：1秒 → **立即**（用户要求更快响应）
- **鼠标离开延迟**：1秒 → **立即**（用户要求更快响应）
- **动画时长**：300ms → **150ms**（性能优化）
- **动画帧率**：60fps → **15fps**（性能优化，减少 IPC 调用）

**鼠标检测方式的变更：**
- **原计划**：Rust 后端追踪鼠标位置，检测 5px 触发区域
- **实际实现**：前端监听窗口的 `mouseenter`/`mouseleave` 事件
- **变更原因**：10px 可见区域足够大，直接监听窗口事件更简单
- **实际效果**：响应及时，实现简单

### 11.2 实际实现的技术架构

**文件结构：**
```
src/types/window.ts              # TypeScript 类型定义
src/stores/windowStore.ts        # Pinia 状态管理
src/composables/useWindowSnap.ts # 前端 composable 函数
src/components/SnapPreview.vue   # 预览框组件
src/App.vue                      # 主应用，集成拖动逻辑
src/main.ts                      # 根据窗口 label 渲染不同组件
src-tauri/src/window_snap.rs     # Rust 后端逻辑
```

**Rust 命令：**
- `get_current_screen_info()` - 获取屏幕信息
- `determine_snap_edge()` - 判断吸附边缘
- `calculate_snap_position()` - 计算吸附位置
- `snap_to_edge()` - 执行吸附（先设置位置，再设置尺寸）

**前端函数：**
- `hideWindow()` - 隐藏窗口（150ms/15fps 动画）
- `showWindow()` - 显示窗口（150ms/15fps 动画）
- `restoreOriginalState()` - 还原窗口状态（只还原尺寸，不还原位置）
- `startDrag()` - 开始拖动，取消自动隐藏，处理隐藏状态
- `onMouseMove()` - 拖动中更新位置（60fps 节流）和预览（10fps 节流）
- `onMouseUp()` - 拖动结束，检测吸附
- `onMouseEnter()` - 鼠标进入，显示窗口
- `onMouseLeave()` - 鼠标离开，立即隐藏窗口

### 11.4 已解决的关键问题

**问题1：吸附后窗口闪烁两次**
- **原因**：窗口移动触发 `mouseleave`，导致 `hideWindow()` 被调用两次
- **解决**：添加 `isHiding`/`isShowing` 标志，防止重复调用

**问题2：吸附后窗口超出屏幕**
- **原因**：Rust 端先设置尺寸再设置位置，尺寸改变导致位置偏移
- **解决**：交换顺序，先设置位置再设置尺寸

**问题3：动画卡顿**
- **原因**：频繁的 IPC 调用（60fps = 每秒 60 次）
- **解决**：降低帧率到 15fps，动画时长缩短到 150ms，使用 await 等待更新

**问题4：2px 可见区域太窄**
- **原因**：鼠标很难精确悬停在 2px 区域
- **解决**：增加可见区域到 10px
